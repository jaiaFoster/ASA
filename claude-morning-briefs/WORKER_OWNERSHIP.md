# Morning Brief Worker Ownership

Supersedes the 2026-11-13 reconciliation (#602). Separates *intake*, *semantic triage*, and
*implementation*. It does not change ASA governance or confer standing authority.

Pipeline: **Morning brief → Actions intake → Claude Triage Routine → canonical GitHub issues →
Claude Engineering Routine → tested PR → human review/merge.**

## Single-owner responsibilities

| Actor | Owns | Must not do |
| --- | --- | --- |
| GitHub Actions `morning-brief-engineer.yml` (08:00 America/Phoenix) | Deterministic intake: one intake issue per brief *id*, revision notices when content changes, duplicate-intake healing; runs the unit tests first | Interpret briefs; edit code; write ledger records; call any AI API; hold write scopes beyond `issues` |
| Routine A — Claude Morning Brief Triage (09:00) | Full per-brief reconciliation; canonical issue creation/linking; per-observation dispositions via `run.py ledger-record`; cursor mirror PR | Implement fixes; merge; mark a brief reviewed without complete dispositions |
| Routine B — Claude Engineering Worker (10:00) | Claim one `engineering-ready` issue; root-cause fix; regression tests; PR; issue progress | Re-ingest briefs; self-authorize architecture/Founder work; merge/deploy; work an issue with a live claim or an open PR |
| GitHub CI (`Product CI`, `Morning Brief Tools CI`, validators) | Checks on PRs | Decide scope |
| Human (Founder / merge authority) | Merge, deploy, `engineering-ready` veto, architecture/Founder decisions | — |

The former ChatGPT Morning Brief Engineer automation is **disabled** and owns nothing. Desktop
Codex/Claude sessions may still take an `engineering-ready` issue but must use the same claim protocol.

## Durable state (GitHub is canonical)

- **Brief identity** = filename stem (`2026-10-08`, `2026-10-14-postopen`); **content hash** = sha256.
  Source roots: `claude-morning-briefs/` (canonical) and `briefs/` (where the daily producer task
  currently writes); canonical wins on collision.
- **Intake issue** (`BRIEF INTAKE: engineering review <id>`) holds the marker
  `<!-- asa-brief-intake:v2 id=… sha256=… -->` (legacy v1 markers are still recognized). A changed
  file adds one `asa-brief-revision` comment (idempotent) and reopens the issue.
- **Ledger records** are structured comments (`asa-brief-ledger:v1`), validated before posting.
  States derive from them: `discovered → queued → reviewing → reviewed → completed`. A stale
  `reviewing` record (>12 h) or a hash mismatch returns the brief to `queued`.
- **Engineering claims** are `asa-claim:v1` comments. First claim in comment order wins, TTL ≤ 12 h
  measured on GitHub timestamps, heartbeat extends, release frees, expiry = stale-claim recovery.
  Only comments from OWNER/MEMBER/COLLABORATOR count (forged claims/reviews are ignored).
- `ENGINEERING_REVIEW_CURSOR.yaml` is a **derived mirror** regenerated by `run.py sync-cursor`;
  it never decides state. Merging the mirror PR is a human action.

## Authorization convention

Only issues labelled `engineering-ready` are eligible for Routine B. The triage routine may apply it
solely to bounded fixes inside existing authority (assignment §5 Step D). `needs-architect` and
`needs-founder` are never auto-selected. No agent is granted standing permission to merge, deploy,
use production credentials, or override Founder/Architect approval.
